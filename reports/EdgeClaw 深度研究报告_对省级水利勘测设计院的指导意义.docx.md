# 1. EdgeClaw 技术深度解析

## 1.1 技术背景

### OpenClaw 的局限性

OpenClaw（俗称「龙虾」）是 2025 年底爆红的开源 AI 助手框架，但存在两大核心问题：

| 问题 | 描述 | 影响 |
|------|------|------|
| **数据安全风险** | 默认配置存在高危漏洞 | 提示词注入、误操作、插件投毒 |
| **成本高昂** | 所有任务上云处理 | Token 费用居高不下 |

### EdgeClaw 的创新

EdgeClaw 在 OpenClaw 基础上，增加了**端云协同架构**，核心创新包括：

```
┌─────────────────────────────────────────────────────────────┐
│                    EdgeClaw 技术架构                          │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   用户任务 → 隐私路由 (GuardAgent) → 智能分流               │
│                      │                                      │
│         ┌────────────┼────────────┐                         │
│         ▼            ▼            ▼                         │
│      S1 公开      S2 敏感      S3 绝密                       │
│      云端模型     脱敏上云      本地处理                      │
│      (最强能力)   (平衡方案)    (绝对安全)                    │
│                                                             │
│   本地引擎：MiniCPM 系列 (端侧最强模型)                       │
│   - 文本清洗、格式转换、信息抽取                              │
│   - 零 Token 消耗、断网可用                                   │
│                                                             │
│   双轨记忆机制：                                              │
│   - 云端：只能看到脱敏后的对话历史                            │
│   - 本地：完整记忆 (含敏感信息)                               │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 1.2 核心技术详解

### 1.2.1 隐私路由协议（S1/S2/S3）

| 等级 | 数据类型 | 处理方式 | 水利场景示例 |
|------|---------|---------|------------|
| **S1 公开** | 不涉及隐私 | 直接调用云端最强模型 | 气象预报查询、行业规范检索 |
| **S2 敏感** | 需保护但非绝密 | 自动脱敏后上云 | 项目名称→代号、地名→坐标 |
| **S3 绝密** | 核心商业/国家机密 | 强制本地处理、物理隔绝 | 大坝设计参数、水库库容、涉密工程 |

### 1.2.2 GuardAgent 工作流程

```
用户任务
   │
   ▼
┌─────────────────────────────────┐
│  GuardAgent (隐私路由中间件)     │
│  1. 拦截任务指令                 │
│  2. 识别敏感等级 (NLP 分类)       │
│  3. 执行路由策略                 │
│  4. 记录审计日志                 │
└─────────────────────────────────┘
   │
   ├──→ S1 → 云端模型 (Qwen/GLM/Claude)
   ├──→ S2 → 脱敏引擎 → 云端模型
   └──→ S3 → 本地模型 (MiniCPM)
```

### 1.2.3 本地引擎（MiniCPM 系列）

**技术特点：**
- 端侧最强模型之一（面壁智能研发）
- 参数规模紧凑，推理速度快
- 支持文本清洗、格式转换、信息抽取
- **零 Token 消耗**
- **断网可用**

**处理能力：**
- 98% 的常规任务本地完成
- 仅 2% 的疑难杂症上云处理

## 1.3 性能与成本对比

| 指标 | 纯云端方案 | EdgeClaw | 改善幅度 |
|------|-----------|---------|---------|
| **Token 成本** | 100% 上云 | 2% 上云 | **降低 98%** |
| **响应速度** | 依赖网络 | 本地即时 | **提升 5-10 倍** |
| **断网可用** | ❌ 不可用 | ✅ 可用 | **100% 可用** |
| **数据泄露风险** | 高 | 极低 | **降低 95%+** |
| **复杂任务能力** | 强 | 强 (云端兜底) | **持平** |

## 2.2 数据安全挑战

### 水利数据敏感等级分布

```
S3 绝密数据 (约 40%)
├── 大坝设计参数 (结构、材料、荷载)
├── 水库库容曲线、调度规程
├── 涉密工程 (军事、战略)
├── 地质勘探核心数据
└── 水文站实测原始数据

S2 敏感数据 (约 45%)
├── 项目名称、地点
├── 投资金额、合同信息
├── 一般监测数据
├── 设计图纸 (非核心)
└── 客户信息

S1 公开数据 (约 15%)
├── 气象预报
├── 行业规范标准
├── 公开论文资料
└── 政策法规
```

### 当前安全风险

| 风险类型 | 具体表现 | 潜在后果 |
|---------|---------|---------|
| **云端泄露** | 使用公有云 AI 处理涉密数据 | 国家秘密泄露、商业机密外流 |
| **权限失控** | 外包人员访问敏感数据 | 数据被复制、转卖 |
| **供应链风险** | 第三方软件后门 | 数据被窃取、系统被控制 |
| **合规风险** | 不符合等保 2.0、保密法 | 行政处罚、资质吊销 |

# 3. 应用场景落地

## 3.1 场景一：勘测报告智能编写（S3 绝密）

### 现状
- 工程师手工编写，耗时 3-5 天
- 涉密地质数据不能上云
- 规范检索效率低

### EdgeClaw 方案

```
┌─────────────────────────────────────────────────────────┐
│  勘测报告智能编写流程                                    │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  1. 野外勘测数据 → 本地 MiniCPM → 自动整理              │
│     (GPS 坐标、岩性描述、照片)                           │
│                                                         │
│  2. 规范检索 → 云端大模型 → 返回适用条款                │
│     (不涉及项目信息，S1 公开)                            │
│                                                         │
│  3. 报告初稿 → 本地 MiniCPM → 自动撰写                  │
│     (涉密数据留本地)                                     │
│                                                         │
│  4. 质量校审 → 本地 MiniCPM → 规范符合性检查            │
│                                                         │
│  5. 最终报告 → 工程师审核 → 提交                        │
│                                                         │
└─────────────────────────────────────────────────────────┘

效果：3-5 天 → 0.5 天，效率提升 6-10 倍
```

### 技术要点
- 地质数据 S3 级，100% 本地处理
- 规范检索 S1 级，可上云
- 双轨记忆：本地保存完整报告历史

## 3.2 场景二：大坝安全监测预警（S3 绝密）

### 现状
- 24 小时人工值守
- 异常识别依赖经验
- 预警响应慢

### EdgeClaw 方案

```
┌─────────────────────────────────────────────────────────┐
│  大坝安全监测智能预警                                    │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  监测数据 → 本地 MiniCPM → 实时分析                     │
│  (渗压、位移、应力，全部 S3 级)                          │
│                                                         │
│  ├── 正常 → 自动记录 → 生成日报                         │
│  │                                                      │
│  └── 异常 → 本地预警 → 推送责任人                       │
│       │                                                 │
│       └── 复杂诊断 → 脱敏后上云 → 专家系统辅助          │
```
